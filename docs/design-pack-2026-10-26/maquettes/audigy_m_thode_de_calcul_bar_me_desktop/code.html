Méthodologie & Barème d'évaluation

Cette page détaille la manière dont Audigy mesure, pondère et calcule les scores de santé technique web en totale transparence, sans captation de données et avec une fidélité d'observation reproductible.

Démarche méthodologique

Le processus d'audit passif en 3 étapes

1

Collecte passive non-intrusive

Requêtes HTTP et DNS standard strictement passives. Zéro injection SQL, ni fuzzing, ni test de charge : conformité absolue aux standards navigateurs.

GET / HEAD neutres
2

Analyse multidisciplinaire

Calcul croisé et transparent sur 7 piliers actifs pondérés selon les référentiels officiels internationaux (ISO/IEC, WCAG 2.2, RGAA 4.1, GreenIT).

7 piliers pondérés /100
3

Synthèse & Brief remédiation

Rapport transparent horodaté RFC 3161 avec plan d'action hiérarchisé par criticité technique, sans jargon commercial ni pénalité arbitraire.

Zéro traceur tiers ni revente de données

Formule de calcul & reproductibilité

Le score global d'un site web sur Audigy n'est pas une appréciation arbitraire : il est le produit d'une moyenne pondérée stricte entre les 7 piliers actifs notés (le pilier Disponibilité faisant l'objet d'un statut binaire sans fausser la note technique).

// Formule de calcul du Score Global Audigy (SGA) :
Score = Σ (Note_Pilier_i × Poids_i) / Σ (Poids_actifs)
Où Poids_actifs exclut automatiquement tout pilier ayant le statut Non testé. Ainsi, un site dépourvu d'enregistrement de messagerie ne subit pas de malus injustifié sur sa note de sécurité.
history_toggle_off

Horodatage RFC 3161

Chaque rapport généré est scellé cryptographiquement selon la norme RFC 3161. L'empreinte SHA-256 de la réponse serveur et du rapport permet d'attester l'état exact du site à la seconde près face à un tiers.

Questions fréquentes sur l'évaluation

Pourquoi le pilier Disponibilité n'a-t-il pas de note chiffrée ? expand_more
La disponibilité est un état binaire : un site est accessible ou ne l'est pas. Intégrer un temps de réponse passager dans la moyenne générale fausserait la note technique relative au code source et aux bonnes pratiques de conformité.
Comment Audigy gère-t-il les pare-feux applicatifs (WAF type Cloudflare) ? expand_more
Nos sondes s'identifient via un User-Agent clair AudigyBot/2026. Si un challenge JS ou un blocage Cloudflare 403/429 se déclenche, les tests concernés basculent automatiquement en Non testé au lieu d'attribuer une note négative punitive.
À quelle fréquence le barème d'évaluation est-il mis à jour ? expand_more
Le barème fait l'objet d'une révision annuelle (ici 2026.1) alignée sur les parutions de nouvelles recommandations (CNIL, RGAA, W3C). Toute évolution majeure est archivée publiquement avec un tableau de conversion pour préserver l'historique des audits antérieurs.
